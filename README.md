## What is exekyute daily builds?

exekyute daily builds gathers many small projects under a single monorepo. Day-to-day experiments, portfolio toolkits, and data-centric builds live side by side so you can open any piece on its own or treat the tree as one shared library of examples.

The audience is anyone studying concrete analytics patterns, open-data work, and reporting pipelines. Expect a reference mix that pairs frozen source data, outputs you can re-check, and artifacts spanning HTML, SQL, Python, JavaScript, TypeScript, Excel, Tableau, Power BI, and DuckDB.

## How to work with the projects

Navigate by folder until you land on the build you want. Every project is meant to stand alone—open it, inspect its data, or line up inputs against the published result.

Suggested path:

1. Select a toolkit, dashboard, or analysis directory.
2. Skim the bundled data snapshots and golden outputs.
3. Launch the HTML page, workbook, or report file.
4. Diff source materials against the finished build.

When scripts ship with a project, run them under the runtime they target—Python, JavaScript, TypeScript, SQL, or a DuckDB flow.

## Project configuration

Settings almost always live next to the project inside the monorepo. Check local config files, workbook options, script flags, or folder notes that describe how that build is produced.

A common shape looks like:

    project/
      data/
      src/
      output/
      config/

Because builds are isolated, options change from toolkit to toolkit. Use the folder you opened as the source of truth for paths, inputs, and report switches.

## FAQ

**How should I begin?**  
Use the download link for the latest build, then open a project folder that matches the skill or domain you want to study.

**Is every project the same kind of work?**  
No. Analytics, visualization, portfolio samples, and smaller utility experiments all appear; content depends on the folder.

**What keeps builds reproducible?**  
Many entries ship source data snapshots plus golden output copies so you can verify the path from input to result.

**Where do I find configuration?**  
Almost always inside the project directory—config files, scripts, workbook settings, or short notes on how output was made.

**A project will not open—what next?**  
Confirm the file type, install or launch the right viewer/runtime, and read any setup notes in that project folder.
